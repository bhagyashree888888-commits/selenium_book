--facilities execution of repeated test cases

--Handles large-scale test matrices efficiently
--->A telecom company must validate thousands of plan combinations (data plans, add-ons, regional variations).

This increases accuracy and allows the finance team to focus only on exceptions.

--save time , cost

After automation:

No need for large manual test teams
Release cycles become faster without increasing QA cost


cons:

Q. what is selenium WebDriver ?
Selenium WebDriver is a library (API) that directly communicates with the browser using browser-specific drivers. 
It interacts with web elements just like a real user, making it fast, stable, and efficient.

---------------------------------------------------------------------------

| Feature             | Selenium 3            | Selenium 4                   |
| ------------------- | ------------------    | ---------------------------- |
| Protocol            | JSON Wire Protocol    | W3C WebDriver                |
| DesiredCapabilities | Used                  |   Replaced by Options        |
| Relative Locators   | ❌ No                 | ✔ Yes                       |
| CDP (DevTools)      | ❌ No                 | ✔ Yes                       |
| Screenshots         | Basic                 |   Full-page, element-level   |
| Selenium Grid       | Hub–Node Architect    |   Distributed Grid 4 Architetcure     
| Window/Tabs         | Manual                |   newWindow() method     

1. W3C WebDriver(Protocol):
Faster & more stable execution: Large test suites (3000+ tests in CI/CD) run faster because no JSON conversion layer. Companies like e-commerce or banking save hours in nightly regression runs.

2. Replaced by Options(DesiredCapabilities)
Better browser configuration: Teams easily set headless mode, disable automation banners, add extensions—important for CI pipelines in Jenkins, GitHub Actions, Azure DevOps.

3.Relative Locators (Relative Locators)
Locating dynamic UI elements: In apps where IDs change frequently (React/Angular apps), QA can locate elements based on position (e.g., “button below username field”). Reduces flaky tests.

4.CDP(chrome DevTools Protocol)
Network monitoring, API failures, and security testing: QA can block ads, mock network responses, capture console logs, check performance timing, or verify if API returns correct status codes during UI flows. Common in fintech, e-commerce, OTT apps

5.Screenshots (Full-page, element-level)
Reporting & debugging: When a test fails in CI, full-page screenshot helps developers quickly understand the bug. Very useful for PDF pages, long dashboards, or invoice pages.

6.Selenium Grid (Distributed Grid 4)
Parallel testing at scale: Companies run hundreds of tests across multiple OS/browsers using Kubernetes/Docker. Stable cross-browser testing with load-balanced nodes.

7.newWindow() method (Window/Tabs)
Handling multi-tab workflows: Useful for apps that open payment gateways, external docs, OTP pages, or “View Details” links in a new tab. Much cleaner code and less flaky switching.
 
W3C (World Wide Web Consortium)
W3C:no JSON conversion.

Selenium WebDriver communicates with browsers using the official W3C WebDriver Protocol, 
not legacy protocols like JSON Wire Protocol.

Q what is Xpath ?
XPath stands for XML Path Language.
XPath is used to locate elements in the DOM when attributes are dynamic or when other locators are not reliable.

------------------------------------------------------------------------------------------
Q. Xpath types ?

1. Absolute XPath:
   Absolute XPath starts from the root node of the HTML document (/html) and follows the complete path to the element.
   Starts with single slash /
   Depends on the complete DOM hierarchy
   Highly fragile — breaks if any node changes 
   Not recommended for automation ,Rarely used

2.	Relative XPath:
	Relative XPath starts from any node in the DOM and uses attributes or relationships to locate elements.
	Starts with double slash //
	Does not depend on full DOM structure
	More stable and flexible
	Supports functions like contains(), text(), starts-with()

==================================================================================================================
Q.Diffrence in absolute vs relative xpath?

| Point       | Absolute XPath  | Relative XPath    |
| ----------- | --------------- | ----------------- |
| DOM usage   | Full hierarchy  | Partial hierarchy |
| Start point | `/html`         | `//`              |
| Dependency  | Structure-based | Attribute-based   |
| Stability   | Low             | High              |

---------------------------------------------------------------------------------------------
Q.why Absolute XPath is not used?
Absolute XPath is tightly coupled to the complete DOM hierarchy, whereas Relative XPath minimizes dependency on the DOM hierarchy by relying on element attributes and logical conditions, making it more stable.

==========================================================================================================================
Q.why to use Relative xpath ?
In real projects, DOM structure changes frequently. Absolute XPath depends on the full hierarchy, so it’s very fragile. Relative XPath depends on stable attributes or nearby elements, so scripts don’t break often and maintenance is easier.”

Q.What is an Alert in Selenium?
In Selenium, JavaScript alerts (alert, confirm, prompt) are browser-managed modals that block the UI and exist outside the HTML DOM. Since they are not DOM elements, Selenium handles them by switching context to the Alert interface to perform actions like accept, dismiss, read text, or send input, ensuring uninterrupted test execution.

Q. What happens if an Alert is not handled?
If a JavaScript alert is present and Selenium tries to perform any action on the page without handling it, Selenium throws an UnhandledAlertException because the browser’s UI thread is blocked by the alert.
1.JavaScript alerts are modal and synchronous
2.Browser halts DOM interaction until alert is resolved
3.WebDriver cannot execute commands on the DOM while alert is active
✔ Test execution terminates or skips further steps

// Step 1: Store the parent window ID
String parentWindow = driver.getWindowHandle();

// Step 2: Click something that opens a new (child) window
driver.findElement(By.linkText("Open Child Window")).click();

// Step 3: Get all window handles
Set<String> allWindows = driver.getWindowHandles();

// Step 4: Switch to child window
for (String window : allWindows) {
    if (!window.equals(parentWindow)) {
        driver.switchTo().window(window);
        
        // ✅ Step 5: Perform actions on the child window
        System.out.println("Child Title: " + driver.getTitle());
        driver.findElement(By.id("childInput")).sendKeys("Hello from Child!");

        // Optional: Close child window
        driver.close();
        
        // Break after switching once
        break;
    }
}

// Step 6: Switch back to the parent window
driver.switchTo().window(parentWindow);
System.out.println("Back to Parent: " + driver.getTitle());

Q.findElement() meaning?

findElement() is a method used to locate a single element on the webpage.return type:web element.
It is part of the WebDriver interface.
Returns the first matching element it finds based on the locator you provide.
If no element is found, it throws NoSuchElementException.
By is a utility class in Selenium that provides locator strategies to find elements

19 encapsulation eg?

public class Browser {
    // Private WebDriver instance, so it's encapsulated (hidden)
    private WebDriver driver;

    // Constructor: Initializes the WebDriver
    public Browser() {
        // Encapsulated driver setup: hidden from the outside
        System.setProperty("webdriver.chrome.driver", "path/to/chromedriver");
        this.driver = new ChromeDriver();  // Chrome browser
    }

    // Public method to open a URL in the browser
    public void openURL(String url) {
        driver.get(url);
    }

    // Public method to close the browser
    public void closeBrowser() {
        driver.quit();
    }

    // Public method to get the title of the current page
    public String getPageTitle() {
        return driver.getTitle();
    }
}
-----------
public class TestEncapsulation {
    public static void main(String[] args) {
        // Creating a Browser object
        Browser myBrowser = new Browser();

        // Using the public methods to interact with the browser
        myBrowser.openURL("https://example.com");
        System.out.println("Page Title: " + myBrowser.getPageTitle());
        
        // Close the browser
        myBrowser.closeBrowser();
    }
}
 What’s Encapsulated Here?
Driver Setup: The System.setProperty() and ChromeDriver instantiation are hidden inside the 
Browser class. The user doesn’t need to know how the WebDriver is set up.

Browser Operations: Operations like opening a URL, closing the browser, and getting the page 
title are exposed as public methods — users of the Browser class only interact with these 
methods.

Private Data: The WebDriver instance is private to the Browser class. It cannot be accessed 
directly outside of it. You can only control it through the provided public methods.
------------------------------------------------------------------------------
	
20Q: Why is WebDriver private in the Browser class?	
To encapsulate the WebDriver setup and prevent direct modification from outside the class.

21Q: What benefit does this encapsulation provide?	
It simplifies the interface for users, hiding the internal complexity of WebDriver setup and 
interactions.

22Q: Can you access driver directly outside of Browser class?	
No, it's a private variable. You must use the public methods.
