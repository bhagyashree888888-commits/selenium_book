Q. What Is Database?
A database is a structured collection of data stored and managed by an RDBMS, enabling efficient CRUD operations using SQL. 
In QA, it is used to validate backend data integrity and consistency across UI, API, and database layers.

Q. What is Database Management System (DBMS)?
A Database Management System (DBMS) is system software that provides an interface to define, store, retrieve, update, and control access to data in a database. 
It handles data storage, security, concurrency, backup, and recovery.

Examples: FoxPro, dBase (database software ,store data in files (like .dbf files)
--------------------------------------------------
Q. What is Relational Model ?
A Relational Database Management System (RDBMS) is a DBMS that is based on the relational model. 
It organizes data into tables and allows relationships between them.

Features of RDBMS:
Uses SQL for querying data.
Maintains data integrity and ACID properties (Atomicity, Consistency, Isolation, Durability).
Supports relationships through primary and foreign keys.
Allows multi-user access and transactions.

Examples: MySQL, Oracle, PostgreSQL, Microsoft SQL Server.

//ACID :
automicity - a transaction must either succeed completely or not run at all
Consistency – Rules are never broken (Rules always followed)
Isolation –  Transactions don’t disturb each other
Durability – Once saved, it stays saved

Scenario: Transfer ₹100 from Person A to Person B

A – Atomicity
Either both actions happen or none
A balance −100
B balance +100
✔ If money is deducted from A but not added to B → ROLLBACK

C – Consistency
Total money stays correct
Before transfer: A + B = same total
After transfer:  A + B = same total
✔ No negative balance allowed

I – Isolation
Real-Time Scenario (ATM A and ATM B at different locations)
Initial balance = ₹1000
Both A and B insert cards at the same time.

Step-by-Step What Actually Happens
⏱️ Time 0 seconds

ATM A → request to withdraw ₹700
ATM B → request to withdraw ₹500

Both ATMs:
✔ show menus
✔ allow user to enter amount
✔ look “active”

What the DATABASE Does (Isolation Logic)
Step 1: Transaction A reaches DB first
BEGIN;
SELECT balance FROM accounts WHERE account_id='A'; -- 1000
🔒 Database places a lock on account A
(This is automatic, user doesn’t see it)

Step 2: Transaction B reaches DB
BEGIN;
SELECT balance FROM accounts WHERE account_id='A';
🚦 B is put in WAIT state at DB level

ATM screen still shows “Processing…”
User thinks system is working
No balance is shown yet

Step 3: Transaction A completes
UPDATE accounts SET balance = balance - 700;
COMMIT;
✔ Balance now = ₹300
✔ Lock is released

Step 4: Transaction B resumes
SELECT balance FROM accounts WHERE account_id='A'; -- 300
❌ ₹500 > ₹300
➡ Insufficient balance message shown

What ATM Machine Shows to B During Wait?
💡 Very important

ATM does NOT show:
Balance
Error
Old data

ATM shows:
“Please wait”
“Processing transaction”
Loading screen

This wait is usually:
Milliseconds to a few seconds
NOT the full 1–2 minutes of user input time

D – Durability
Once transfer is done, it stays done
COMMIT;
✔ Even if system crashes, transfer remains saved

They ensure data integrity by restricting the kind of data that can be stored.

Q.  when to use float ,decimal ,double ?

1. DECIMAL (or NUMERIC) :Bank balances, taxes, invoices, product prices
	tax DECIMAL(10,2)  -- max 99999999.99
	price DECIMAL(12,4) -- max 9999999999.9999
Exact storage of decimal numbers                   (use decimal in projects)

2. FLOAT :4 bytes,Physics simulations, sensor readings, 3D coordinates, percentages where small errors are okay
	temperature FLOAT
	weight FLOAT
	sensor_reading FLOAT
float a = 1.1234567f;    // 7 digits precision
double b = 1.123456789012345; // 15 digits
DOUBLE  : 1.1234567890123456   -- rounded after ~15 digits
DECIMAL: 1.12345678901234567890 -- exact

3. DOUBLE (or REAL) : Space calculations, physics engines, probability computations, statistical analysis
	astronomical_distance DOUBLE
	pi_approximation DOUBLE
	large-scale simulations DOUBLE
More precise than FLOAT, can store very large or very small numbers.

Answer: 
• CHAR(n) – Fixed-length storage. Always takes n bytes even if data is shorter. 
• VARCHAR(n) – var is Variable-length storage. Uses only the space required. //VARCHAR(n) can go up to 65,535 bytes.

• What are Constraints?
Constraints are rules applied to table columns to enforce data integrity. 
They control the type of data that can be inserted, updated, or deleted.

• Types and Examples.
| **Constraint**  | **Purpose**                                 | **Example**                                                                 |
| --------------- | ------------------------------------------- | --------------------------------------------------------------------------- |
| **PRIMARY KEY** | Unique identifier for each row              | `AccountID INT PRIMARY KEY`                                                 |
| **FOREIGN KEY** | Ensures value exists in another table       | `CustomerID INT, FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)` |
| **NOT NULL**    | Column cannot have NULL values(mandatory)              | product_name VARCHAR(100) NOT NULL,                                        |
| **UNIQUE**      | values must be unique                   | `AccountNumber VARCHAR(20) UNIQUE` ,passport_number                                         |
| **CHECK**       | Ensures column values satisfy a condition(validation)   |  price DECIMAL(10,2) CHECK (price > 0) product price cannot be negative                                |
| **DEFAULT**     | Assigns a default value if none is provided |  order_date DATE DEFAULT CURRENT_DATE,                                            |


• How to use.

CREATE TABLE Accounts (
    AccountID INT PRIMARY KEY,
    CustomerID INT,

Q . What is a primary key? Can  a   table    have   multiple   primary  keys? 

A primary key is a column (or set of columns) that  uniquely  identifies   each  row   in  a  table  and  does  not  allow  NULL    values. 

CREATE TABLE students ( 
    student_id INT PRIMARY KEY, 
    name VARCHAR(50) 
); 

• A table can have only one primary key constraint, but that key can be a composite key (multiple  columns). 
| A | B | C | Allowed?                              |
| - | - | - | --------------------------------------|
| 1 | 2 | 3 | ✅ Yes (first row)                    |
| 1 | 2 | 4 | ✅ Yes (combination is unique)        |
| 1 | 3 | 3 | ✅ Yes (combination is unique)        |
| 1 | 2 | 3 | ❌ No (same combination as first row) |

The    combination    of   all   three   columns   cannot      repeat.
But     individual    values      (like A = 1 or B = 2) can   appear   in    multiple  rows,  as     long      as   the     full    combination (A, B, C)     is    unique.

QA use case: When inserting test data, you must ensure primary key values are unique to avoid errors.

Q. What is a foreign key and why is it important in testing? 

A foreign key is a column in one table that refers to the primary key in another table, establishing a relationship  between tables. 

CREATE TABLE orders ( 
    order_id INT PRIMARY KEY, 
    customer_id INT, 
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id) 
); 

Importance for QA: 
• Ensures referential integrity (you cannot have an order without a valid customer). 
• While testing, you must insert data in the correct order (parent first, then child). 
Helps verify delete/update behavior (cascade or restrict).

Q . What is the difference between DELETE, TRUNCATE, and DROP? 
Answer: 
• DELETE – Removes specific rows from a table based on a WHERE clause. 
The table structure remains. Row level
Transaction logs are kept, so you can rollback if needed. 
//DELETE does NOT reset AUTO_INCREMENT

DELETE FROM employees WHERE department = 'HR'; 
--------------------------
Truncate : Removes all rows from a table, resets identity counters, and is faster than DELETE. 
You cannot rollback in most databases. Table level
TRUNCATE TABLE Employees;
//After TRUNCATE, the auto-generated ID starts again from the beginning (usually 1).
----------------------------------
• DROP – Completely removes the table and its structure from the database. Object level (table, view, index)
DROP TABLE employees; 

QA relevance: Knowing the difference helps avoid accidental data loss when preparing or cleaning test data.

1. INNER JOIN

SELECT product_name, customer_name

INNER JOIN Customer
ON Product.product_id = Customer.product_id;

| product_name | customer_name |
| ------------ | ------------- |
| Laptop       | Alice         |
| Mobile       | Bob           |

//SELECT *

❌ MySQL allows comparing INT with VARCHAR, but the logic is wrong
SQL, joins are almost always done between columns of the same (or compatible) data type

QA Perspective:
Verify only matching rows appear.
Test edge cases: no matching rows → result should be empty.
Test duplicate CustomerIDs → all matches should appear.
-------------------------------------------------------------------------

2. LEFT JOIN
   ➤ Returns: All rows from the left table and matching rows from the right table (NULL if no match).
   ➤ Banking Example: Shows all customers, even those without accounts.

Returns all rows from left table (Product) and matching from right table //Note : all rows from left table (Product)

SELECT product_name, customer_name
FROM Product                                                  //left table
LEFT JOIN Customer
ON Product.product_id = Customer.product_id;

| product_name | customer_name |
| ------------            | ------------- |
| Laptop               | Alice         |
| Mobile               | Bob           |
| Tablet               | NULL          |

QA Perspective:
Verify all left table rows appear, even if there’s no match.
Check NULLs for unmatched rows.
Edge cases: left table empty → result should be empty.
--------------------------------------------------------------------------
3. RIGHT JOIN
   ➤ Returns: All rows from the right table and matching rows from the left table (NULL if no match).

SELECT *
FROM Product                                                  
RIGHT JOIN Customer                                           //right table
ON Product.product_id = Customer.product_id;

Alice    laptop
Bob      mobile
Charlie   null

In a RIGHT JOIN, the table after RIGHT JOIN is considered the right table.
 All its rows are returned, and matching rows from the left table are included. If no match exists, the left table columns are NULL

QA Perspective:

query inside another query.

The main query is called the outer query.
The subquery executes first, and its result is passed to the outer query

a) Single-row Subquery
A single-row subquery returns only one row (and usually one column) as its result. 
It is typically used with comparison operators like =, <, >, <=, >=, or <>.

Query: Find the customer with the highest balance.

SELECT CustomerName, Balance
FROM Accounts
WHERE Balance = (SELECT MAX(Balance) FROM Accounts);

Outer query fetches CustomerName with balance = 9000 → David
---------------------------------------------------------------------------------------------
b) Multiple-row Subquery
A multiple-row subquery can return more than one row. 
It is usually used with operators like IN, ANY, ALL, or EXISTS.

Query: Find customers whose balance is greater than average.

SELECT CustomerName, Balance
FROM Accounts
WHERE Balance > (SELECT AVG(Balance) FROM Accounts);

Subquery (SELECT AVG(Balance) FROM Accounts) → 5800
Outer query fetches rows where Balance > 5800 → Bob (7500), David (9000)

Midtown → 9000
Outer query filters branches with AvgBalance > 5000 → Uptown, Midtown

Q . What is normalization and why is it important in databases? 

Normalization is a database design technique used to organize data in a relational database efficiently
Normalization is usually done in stages called normal forms:

----------------------------------------------------
1. First Normal Form (1NF) : 
Each column must contain atomic (indivisible) values.
Each row must be unique.
No repeating groups or arrays.

//Not atomic (wrong in 1NF):
StudentID	Name	Courses
1	        Alice	Math, Physics

Not 1NF → courses are multiple values in one column

1NF Version:
StudentID	Name	Course
1	        Alice	Math
1	        Alice	Physics

//Primary Key (composite): (StudentID, Course)
---------------------------------------------------------------
2. Second Normal Form (2NF) :

Already in 1NF.
No partial dependency: every non-key column must depend on the whole primary key, not just part of it.
Only relevant if the primary key is composite. 

Problem in 1NF Table
Primary Key = (StudentID, Course)
Name depends only on StudentID, not on Course
❌ Partial dependency → violates 2NF

Solution: Split into two tables:

//2NF Solution (Split Tables) :
Students Table :
StudentID	Name
1		Alice

StudentCourses Table
StudentID	Course
1		Math
1		Physics

✅ Now:

Name depends fully on StudentID
No partial dependency
Tables are in 2NF
---------------------------------------------------------------

3. Third Normal Form (3NF)
Rule :
Must be in 2NF
No transitive dependency
(Non-key attributes must not depend on other non-key attributes)
Third Normal Form (3NF) → Most widely used

Check for Transitive Dependency :
StudentID → Name
No other non-key attribute depends on Name
✅ No transitive dependency

Solution: Split:
Students: StudentID, Name, Department
Departments: Department, DeptHead

QA importance: Understanding normalization helps in writing joins for related data correctly. 
---------------------------------------------------------------------
| Normal Form | Rule                                 |
| ----------- | ------------------------------------ |
| 1NF         | Atomic values, unique rows           |
| 2NF         | 1NF + no partial dependency          |
| 3NF         | 2NF + no transitive dependency       |
| BCNF        | Every determinant is a candidate key |

Q. What is denormalization, and when might QA encounter it? 
Denormalization is the process of combining tables or adding redundant data to improve read performance at 
the expense of storage space. 
Example: 
• Instead of keeping customer details in a separate table and joining every time, some systems store them 
directly in the orders table for faster reporting. 
QA relevance: When testing reporting systems or data warehouses, denormalization is common — you 
need to ensure data consistency across multiple redundant storage locations.

---> Transaction Control Language (TCL)
TCL (Transaction Control Language) commands are used to manage transactions in a database — that is, to ensure that a group of DML statements (like INSERT, UPDATE, DELETE) are executed as a single unit of work.

| Command             | Purpose                                                      |
| ------------------- | ------------------------------------------------------------ |
| **COMMIT**          | Saves all changes made during the transaction permanently    |
| **ROLLBACK**        | Undoes changes made during the transaction                   |
| **SAVEPOINT**       | Sets a point within a transaction to which you can roll back |
| **SET TRANSACTION** | Defines transaction properties (like read/write mode)        |
